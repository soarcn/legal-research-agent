# Domain documentation

This is a single-context repository.

## Required reading

Before exploring or changing the project:

1. Read the root `CONTEXT.md`.
2. Read the ADRs under `docs/adr/` that affect the work.
3. Use the defined domain terms consistently.
4. Do not silently contradict an accepted ADR.

If a required concept is absent or ambiguous, use domain modelling to resolve it and update `CONTEXT.md`.

## Layout

- `CONTEXT.md` — canonical project vocabulary
- `docs/adr/` — system-wide architecture decisions

When a proposed change conflicts with an ADR, identify the conflict explicitly and decide whether the ADR should be superseded.
